Hi, I'm Kartik Shanbhag. I'm a product manager at Sportz Interactive, building real-time data products — and these are the things I built to prove I could.

Five years in sports data at broadcast scale. I own products where a defect isn't a bug report, it's visible to everyone watching. Auctions broadcast live. APIs behind scoreboards.

Then I go home and build the same class of system alone, in public, with the failures written down.

Three claims, each with proof attached

01Runs by itself

I ship things that run unattended.

I built a model that predicts how the Premier League season will finish. It updates itself every week, then marks its own past predictions to show whether it was right. I don't touch it.

PL Supercomputer 02What didn't work

I publish what didn't work.

Four ideas I tried didn't make the model any better. So I switched them off and wrote down the numbers that proved it. The code for the failed versions is still public.

What I got wrong 03Limited downside

I make being wrong cheap.

My fantasy football bot uses AI to read team news, but it's only allowed to mark a player down, never up. If the AI is wrong, it costs me one player instead of my whole team.

Why this page exists

A product manager should be able to show you the thing.

Most of my professional work sits behind client NDAs and inside broadcast graphics you've seen without knowing whose feed drove them. That's a hard thing to prove on a résumé, so I stopped trying to.

Instead, everything on this site that carries a number is either something you can click and watch running, or something whose backtest script is in a public repository next to it. Where a model of mine failed, the failed version is still in the code and the results are on the page.
